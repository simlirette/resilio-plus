### 6. CORS Wildcard Risk

**Current state:** CORS `allow_credentials=True` with explicit origins from `ALLOWED_ORIGINS` env var. Default includes localhost dev ports.

## V4 known limits (2026-08-19)

Deliberate scope calls from the text-coach build. None blocks the V4 acceptance
run; each is written down so nobody rediscovers it the hard way.

### 11. Onboarding thread state is process-local

**File:** `backend/app/graphs/onboarding.py` — `_thread_states` is a module-level dict.
**Issue:** Restarting the backend mid-onboarding loses the block position; the
next message restarts at block 1. The plan-generation graph does not have this
problem (it uses the SQLite checkpointer).
**Action:** Move the onboarding graph onto the same `SqliteSaver` checkpointer as
`coaching_graph`. Untouched here because it is Phase D code, not V4 transport.

### 12. `CoordinatorService` only runs graphs when an invoker is injected

**File:** `backend/app/services/coordinator_service.py`
**Issue:** The module-level `coordinator_service` singleton — which
`POST /coordinator/dispatch` uses — still returns `pending=True` without
invoking anything. Only surfaces that build their own coordinator via
`build_live_coordinator()` (the Telegram runtime) actually run graphs.
**Justification:** The routing unit tests call `CoordinatorService()` directly
with a live DB; making invocation the default would fire real LLM calls in the
frozen suite. V4 is Telegram-only, so the HTTP surface was left as it was.
**Action:** When a second surface needs it, give the HTTP route a live
coordinator and adapt the routing tests in the same change.

### 13. Telegram `update_id` dedupe is process-local

**File:** `backend/app/integrations/telegram/webhook.py`
**Issue:** The LRU is in memory, so with more than one webhook worker a Telegram
retry can be processed twice. Documented in `TELEGRAM-COACH.md`; mitigated by
running `WEB_CONCURRENCY=1` in webhook mode.
**Action:** Move dedupe into the database (or Redis) if the deployment ever needs
more than one worker.

### 14. Hevy and Terra secrets are stored unencrypted

**File:** `backend/app/routes/link.py` → `ConnectorCredentialModel.extra_json`
**Issue:** The pasted Hevy API key and Terra user id are stored the same way the
existing `POST /athletes/{id}/connectors/hevy` route stores them — plaintext JSON.
Only Strava and Google refresh tokens are Fernet-encrypted.
**Justification:** Encrypting them here alone would break `SyncService`, which
reads the plaintext field. Fixing it means changing both paths at once.
**Action:** Encrypt `extra_json` secrets and migrate existing rows in one change.

### 15. No calendar read-back verification

**File:** `backend/app/integrations/google_calendar/calendar_sync_service.py`
**Issue:** Reconciliation trusts the local `calendar_events` mapping. If someone
deletes a single event by hand in Google Calendar, Resilio will not notice until
the slot's content changes (the patch then 404s and re-inserts).
**Action:** Optional periodic `events.list` sweep matching on
`extendedProperties.private.resilio_slot_id`.

### 16. Single-athlete assumptions in the weekly cycle

**Issue:** `restore_weekly_cycles()` registers a cron per athlete at startup with
no batching, and the pro-activity cap is bypassed for the weekly message. Fine
for one athlete on one box; revisit before multi-tenant.

### 17. The coach speaks French, the transport speaks English

**Files:** `backend/app/graphs/onboarding.py` (`_BLOCK_INSTRUCTIONS`) and the
agent prompts are French; every V4 transport string — button labels, `/help`,
approval confirmations, connect-link text — is English.
**Effect:** cosmetic, verified live on 2026-08-20: the coach opens with
"Bienvenue sur Resilio+" and the buttons underneath read "✅ Approve".
**Justification:** the agent prompts are V1-FROZEN, and T1/T2 shipped their
strings in English before this was visible.
**Action:** pick one language for the athlete-facing surface and move every
V4 string into it. Roughly 40 strings across `messaging/` and
`integrations/telegram/`.

### 18. The test suite is ~30x slower when a real Postgres is reachable

**Measured 2026-08-20:** with `docker compose up -d db` running and
`DATABASE_URL` pointing at it, `pytest tests/` drops to roughly one test per
minute. Stopping the container restores normal throughput (full suite ~16 min).

**Cause:** every `TestClient(app)` startup runs `setup_scheduler()`, which calls
`restore_all_jobs()` and `restore_weekly_cycles()` against the real
`SessionLocal`. With no database listening those fail immediately and are
caught; with one listening they do real work per app startup, and the scheduler
shutdown waits on it. Dozens of API test modules each pay that cost.

**Effect:** invisible until you run the suite while the coach is running, which
is exactly what happens once someone uses V4 daily.

**Workaround:** `docker compose stop db` before `pytest tests/`, or point
`DATABASE_URL` at an unused port for the run.

**Action:** have the test session force `DATABASE_URL` to something unreachable
(or inject a no-op scheduler) so suite timing does not depend on what happens to
be listening on 5432. Touches `tests/conftest.py`, which V4 was forbidden from
modifying, so it is deferred rather than fixed here.

## Won't Fix (documented for completeness)

### Energy Coach as non-agent

The Energy Coach is implemented as pure functions (`energy_patterns.py`, `energy_availability.py`, `allostatic.py`) + graph node rather than a `BaseAgent` subclass. This is a deliberate design decision — energy state detection is stateless computation, not LLM inference. No change needed.

### test_workflows.py legacy tests

The 8 skipped tests cover behaviours that have been superseded by the LangGraph architecture. They are technically dead test code. Keeping them for documentation value is acceptable for V1.0.
