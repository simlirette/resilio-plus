## Contexte et état de départ

### Ce qui existe déjà (backend V1-FROZEN 2026-04-17)

| Composant | Emplacement | Rôle Phase D |
|---|---|---|
| `CoachingService` | `backend/app/services/coaching_service.py` | Wrapper du graphe `plan_generation` existant — à absorber dans `CoordinatorService` |
| Graphe `plan_generation` | `backend/app/core/coaching_graph.py` | Existe en V3-D, étendu en D1 |
| Agents 1-9 | `backend/app/agents/` | Utilisés tels quels — ne pas modifier |
| APScheduler | `backend/app/jobs/` | MonitoringService s'appuiera dessus |
| FastAPI routes | `backend/app/routes/` | Nouvelles routes `coordinator/` et `chat/` en Phase D |
| LangGraph `SqliteSaver` | `data/checkpoints.sqlite` | Checkpointer existant, réutilisé |

### Ce que Phase D construit

1. `CoordinatorService` — point d'entrée unique, routing par `journey_phase`
2. Extension du graphe `plan_generation` (`generation_mode` + `active_plan`)
3. Service `classify_intent` (Haiku 4.5, < 500ms)
4. Graphes : `chat_turn`, `onboarding`, `followup_transition`, `recovery_takeover`
5. `MonitoringService` — événements proactifs, intégration APScheduler
6. Contrats Pydantic B3 v2 partiel + schemas A2 manquants
7. Frontend : chat UI + onboarding flow
8. Dataset eval classify_intent (DEP-C10-009)

### Règle absolue Phase D

**Backend V1-FROZEN = read-only pour les agents et la couche LangGraph existante.**  
Modifications autorisées : ajout de nouveaux fichiers, nouvelles routes, extension du state LangGraph, nouvelles tables Alembic. **Jamais** modifier un agent existant, un test existant, ni mypy/ruff config.
